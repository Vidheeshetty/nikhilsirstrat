1 — Overview

The NTbasedPlatform relies on an extensive automated test-suite to guarantee correctness, stability, and performance. The framework is built on top of pytest and embraces a layered approach ranging from fast unit tests to full system backtests.

2 — Directory Layout

The repository groups tests by purpose:

  • tests/unit/ — pure function/class tests (legacy in legacy_tests/unit/).
  • tests/utils/ — helpers, indicators, data-manager units.
  • tests/runners/ — BatchRunner & strategy runner behaviour.
  • tests/strategies/<name>/ — strategy-specific behaviour (entry/exit).
  • tests/integration/ — orchestrates multiple modules together.
  • tests/system/ — end-to-end backtest via CLI (slow).
  • legacy_tests/ — snapshot of pre-refactor tests kept for regression safety; migrate gradually.

3 — Test Levels

3.1  Unit Tests

Focus on a single function or class. Use fixtures/mocks to isolate external dependencies (file-system, Nautilus objects, network). Tests must be deterministic and finish in <100 ms each.

3.2  Integration Tests

Validate collaboration of several internal modules (e.g. DataManager + EngineManager). They may require small CSV or Parquet samples kept under tests/data/.

3.3  System / End-to-End

Drive the public CLI just like a user would. These tests run the slowest and are marked with @pytest.mark.system so they can be deselected on regular developer loops.

4 — Pytest Configuration

The root pytest.ini captures shared settings:

  • addopts = -ra -q — concise summary report.
  • testpaths = tests — single discovery root.
  • python_files = test_*.py — naming convention.
  • Logging is persisted to pytest.log for post-mortem analysis.

Custom markers: system, integration, slow — see conftest.py for registration.

5 — Writing & Organising Tests

  1. Mirrors package path: src/utils/data_manager.py → tests/utils/test_data_manager.py
  2. Fixture reuse lives in tests/conftest.py.
  3. Prefer pytest.raises and pytest.param over manual try/except.
  4. Keep factories in tests/factories/ (create one if missing).
def test_scale_prices():
    prices = [100, 105, 110]
    scaled = scale_prices(prices, factor=2)
    assert scaled == [200, 210, 220]

7 — Continuous Integration (CI)

GitHub Actions (see .github/workflows/ci.yml) execute the full suite on every push. Failing tests block merges into main.

8 — Customisation Guidelines

When extending the platform:

  • Start with unit tests to specify behaviour before coding.
  • Leverage pytest.param(ids=...) to document scenarios.
  • Tag heavy data-dependent tests with @pytest.mark.slow.
  • Prefer fixture injection over global state.
  • Update coverage threshold if new critical paths are added.
